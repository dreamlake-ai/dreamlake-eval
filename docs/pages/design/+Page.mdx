# Design notes

This is the public working area for DreamLake Eval. Notes distinguish decisions from proposals and explain what evidence would justify a change.

- [Reports across jobs](/design/aggregate-reports): expected inventory, attempts, incomplete results and threshold policy.
- [Pytest, Eval, Dash and MLflow](/design/boundaries): responsibilities and the useful comparison to MLflow's classic evaluation API.
- [Authoring docs and design notes](/design/authoring): edit, preview, review and publish this site.

A useful note starts with a concrete user operation, names the observable behavior, identifies the current implementation, and separates open questions from accepted decisions. Public notes contain technical examples and design rationale; private conversations and operational access details stay in their original workspace.
